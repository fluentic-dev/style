# @fluentic/style v0.1.0-beta.11

## Fix stale CSS in Next.js production builds

Fixed a Turbopack cache-invalidation bug in `@fluentic/style`. Previously, changing a `style()` declaration could change the generated CSS while keeping the same stylesheet URL, allowing returning visitors to see stale styles after a deployment.

Next.js production builds and static exports now use a filename derived from the finished CSS. Changed CSS gets a new URL, and identical CSS keeps its URL. Fluentic’s global cascade order is preserved.

Verified with consecutive Turbopack and Webpack static exports, including a cross-module rule priority check.

## Deployment behavior

Rebuild and deploy the application to generate content-fingerprinted stylesheet
URLs. A CSS change now invalidates the browser/CDN URL naturally; unchanged CSS
retains the same URL. The fingerprint is based on the finished stylesheet, so
rule ordering is preserved rather than reconstructed from separate fragments.

The tagged regression check runs consecutive static exports for both Turbopack
and Webpack and checks a cross-module priority case. This is a production cache
fix, distinct from beta.8's development-cache improvements.
