# @fluentic/style v0.1.0-beta.10

## What’s new

This release improves selector sheets and third-party CSS overrides.

- Selector sheets are now unlayered by default, making third-party overrides more reliable.
- Added the `createSheet({ layer, weight }, items)` overload for per-sheet layer control and increased selector specificity without relying on `!important`.
- Fixed `style.important(...)` priority when cascade layers are enabled.
- Added optional compiler and runtime checks for raw `!important` values and unnecessary important usage.

For regular Fluentic styles, prefer composition or `style.weight(...)`.
Use `style.important(...)` mainly when a selector sheet must override third-party CSS.

## Cascade and configuration details

The per-sheet `layer` option in this version is boolean. Opt in globally with
`css.layer.sheet` or per sheet with `layer: true`; layered sheets use the derived
`<layerNamespace>.sheet` layer. String layer names are a later beta.13 feature.

The per-sheet `weight` increases the generated anchor's specificity. Use it
intentionally when an override must win against another selector. CSS reverses
cascade-layer order for important declarations; this release fixes Fluentic's
important-rule ordering accordingly.

The optional checks are `check.important.rawValue` and
`check.important.outsideSheet`, with `warn` and `error` modes. They help identify
raw `!important` values and important usage outside the sheet-based interop cases
for which it is usually intended.
