# @fluentic/style v0.1.0-beta.15

This beta adds global selector sheets, explicit ordering controls, revised local
sheet layers and specificity, and Next.js development support for RSC globals.

## Changes

- Add `createGlobalSheet(items)` and `createGlobalSheet({ layer, order }, items)`.
  Selectors remain global, without a generated parent class. Client runtime calls
  inject immediately. Static extraction emits CSS and removes the call and inputs
  that become unused.
- Sort whole global sheets by numeric `order`, defaulting to `0`. Orders at or below
  zero precede regular/local rules; positive orders follow them. Equal orders keep
  first discovery first. Local unlayered sheets follow regular styles.
- Rename local sheet `weight` to `specificity`, with a default of `1`. Zero uses
  `:where(.class)`; larger integers repeat the generated anchor class.
- Share ordinary style layers with `layer: true`; keep absolute names literal and
  only prefix relative names when the main layer is enabled. Sheets default to
  unlayered CSS and no longer inherit `css.layer.sheet` or automatically use `.sheet`.
- Split managed important sheet declarations into the first child layer named
  `<resolved-layer>.important`. Use `style.important(value, true)` for native layer
  placement. Unlayered important declarations keep ordinary CSS behavior.
- Carry RSC globals through `data-css-global-seed-dev` and
  `data-css-global-rules-dev`, preserving layer, priority, order, and debug metadata.
  Bridge request globals into Next's HTML renderer for correctly ordered seeds
  before hydration, without mixing concurrent requests. Client adoption,
  navigation, streaming, and HMR replacement/deletion use the shared ordering engine.
- Preserve CSSOM-inserted rules when moving runtime style tags; reorder groups
  without rebuilding unrelated groups. Keep sourcemap/debug metadata intact.
- Support configurable runtime stylesheet documents, disabled injection, and
  reinsertion of cached rules when switching documents.
- Update client and Next.js examples, migrate the Next.js reset from `globals.css`,
  and add a dedicated ordering/cascade guide and global-sheet API reference.
- Generate JSON/Markdown bundle reports and the documentation table together.
  Release validation now rejects stale measurements or mismatched report versions.

## Migration

Replace `createSheet({ weight: n }, items)` with
`createSheet({ specificity: n }, items)`. The old default anchor contributed zero
specificity; add `specificity: 0` explicitly to preserve that behavior.
`style.weight(value, n)` is unchanged and still controls declaration priority.

Choose each sheet's layer explicitly. Replace reliance on `css.layer.sheet` with
`createSheet({ layer: true }, items)` to share ordinary style layers, or use an
explicit named layer when you need separate layer precedence. A leading-dot name
such as `.reset` becomes `reset` when the main layer is disabled.

For layered sheets, choose between managed `style.important(value)` and native
`style.important(value, true)`. Source `order` and Fluentic value weight do not
universally override CSS layer precedence or selector specificity. See the
[ordering guide](https://github.com/fluentic-dev/style/blob/v0.1.0-beta.15/docs/content/src/content/docs/reference/style-ordering.mdx).

A statically extracted global sheet is present in built CSS even if its source
call is inside a function that has not run. Use an authored class/data-attribute
selector for conditional global styles. For Next.js dev, keep the plugin and
`StyleDev` integration enabled. Production globals use extracted CSS.

Measured from the beta.15 build using Vite 8.0.16, production minification, gzip
level 9, and KiB = 1,024 bytes. Reproduce after building with
`pnpm report:bundle:update`; verify with `pnpm report:bundle:check`.

| Extracted generated helpers         |         878 B |         878 |
| Optional named tokens               |      1.20 KiB |       1,225 |
| Full client production runtime      |     28.90 KiB |      29,590 |
| Server extracted production runtime |      5.04 KiB |       5,163 |

| Next.js dev client support          |     18.54 KiB |      18,982 |

The extracted runtime, JSX, generated-helper, and named-token gzip measurements
are unchanged from beta.14. The full client runtime increases from the previously
reported 26.93 KiB to 28.90 KiB (approximately 1.97 KiB). These rows retain selected
public surfaces independently and must not be added together. React/Next host
imports, application definitions, and generated CSS are excluded; other library
dependencies are bundled. Exact imports, externals, and all measurements are in
[the JSON report](https://github.com/fluentic-dev/style/blob/v0.1.0-beta.15/reports/bundle-size.json).
