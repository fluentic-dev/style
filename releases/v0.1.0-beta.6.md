# @fluentic/style v0.1.0-beta.6

This beta version focuses on making framework css-prop adapters, class-name extraction, and Next.js builds feel more predictable in real apps.

- `cssProp` adapters for React, Preact, and Solid now preserve normal JSX prop precedence more reliably when multiple prop chunks are merged.
- JSX `key` stays as a real JSX prop instead of being folded into generated css-prop spreads, preserving list identity in React.
- React Server Component development mode now chooses the correct Fluentic runtime for server and client components when css-prop adapters are enabled.
- Class-name extraction has more stable debug output and better source locations for utilities generated from class-name chains.
- Tailwind-style class-name chains now understand arbitrary text values, including `text-[13px]`, `text-[length:13px]`, and `text-[color:purple]`.
- The Next.js integration improves dev CSS delivery, Turbopack option serialization, and production CSS precollection.
- Common package entry points now include default export conditions for broader resolver compatibility.

## Upgrade considerations

Rebuild applications to pick up the JSX adapter and extraction fixes. In
particular, `key` must retain its framework identity semantics while ordinary
props keep their normal merge precedence. The arbitrary Tailwind text examples
above distinguish size values from explicit color values.

React, Preact, and Solid adapter behavior is covered by this release, but JSX type
augmentation became explicitly framework-specific in beta.7.
