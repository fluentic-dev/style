# @fluentic/style v0.1.0-beta.18

This beta enables persistent compiler caching by default to reduce repeated
production build work.

## Changes

- Cache completed production transforms, including JavaScript, source maps, and
  extracted CSS. Validate input, configuration, compiler/runtime identity, and
  resolved dependency content before reuse.
- Persist immutable tracer syntax metadata as JSON. Reconstruct fresh nodes for
  evaluation; live evaluator bindings remain memory-only.
- Reuse evaluated imports within a build while revalidating and recording their
  dependency chains. Handle missing imports, changed resolution, delayed lazy
  exports, circular imports, and configuration changes.
- Treat corrupt or unreadable cache records as misses and make cache write
  failures nonfatal. Isolate compiler and Node versions in cache namespaces.
- Preserve collected CSS when restoring transforms and avoid unnecessary Vite
  production source-map callbacks that prevent caching.
- Preserve callable token types when passing existing tokens to `createTokens`.

## Migration and limitations

Use the grouped options:

```ts
cache: {
  persistent: true,
  dynamicConfig: true,
  version: '1',
  location: '.cache/fluentic-style',
}
```

All fields are optional; persistence and dynamic configuration caching default to
true. `version` accepts a string or number. Relative locations resolve from the
project root. The old `persistentCache` and plugin `cacheDir` options are removed.

Callbacks are fingerprinted by source without execution on cache hits. Changes to
captured values, external files, environment values, or imported helper behavior
require a `cache.version` bump or cache deletion. Set `cache.dynamicConfig: false`
to bypass completed-transform caching for callback configurations. Native/bound
callbacks, accessors, proxies, and unsupported data still bypass caching.

Check warnings and errors are cached and replayed, including error code frames.
Source, dependency, configuration, or severity changes invalidate those records.
Unrelated compiler and I/O errors are not persisted as check failures.

Set `cache.persistent: false` to disable both disk caches. Changing `cache.version`
selects a new namespace without deleting old entries. Custom parsers and syntax
that JSON cannot preserve bypass syntax reuse. Evaluated bindings remain
memory-only. Restart after changing compiler dependencies.

CI scripts may restore and archive `cache.location` around builds. Transport is
user-managed; compatible Node/compiler versions and matching absolute paths are
needed for reuse. Restored records still undergo validation.

A focused local benchmark compiling 100 files with a shared dependency improved
from a median 552 ms to 189 ms with identical CSS. This is a synthetic tracer
benchmark, not an application build measurement or a performance guarantee.

A second local 100-file benchmark measured median warm transform times of
16.3 ms with callback caching, 16.8 ms without callbacks, and 71.5 ms with callback
caching disabled (five runs). Warm output matched cold output in every case.
The small difference between the two warm-cache cases is measurement noise, not
an advantage attributed to callbacks. These are synthetic benchmark timings.

## Validation

- Frozen-lockfile installation, versioned package build, and bundle report update
  passed with the pinned pnpm 10.17.1.
- `pnpm release:check` passed end to end, including report freshness, workspace
  lint, formatting, documentation checks, and typechecks.
- All 460 library/compiler/runtime tests and bundle-report tests passed, including
  dependency invalidation, resolution changes, corrupt caches, process restarts,
  lazy exports, circular imports, and configuration changes.
- Example and benchmark builds passed. Next.js production verification confirmed
  extracted CSS and rendered routes for `/`, `/ssg`, `/ssr`, `/rsc`, and `/client`.
- The packed beta.18 package passed strict TypeScript 5.9 and 7 consumers under
  Bundler, Node16, and NodeNext resolution. Public types use generated declarations
  without loading implementation sources. React, Preact, Solid, and Tailwind
  tarball consumer builds passed.
