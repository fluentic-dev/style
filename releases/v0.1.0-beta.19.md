# @fluentic/style v0.1.0-beta.19

This beta fixes repeated development stylesheet rebuilds when new styles arrive
with lower priorities after selector or global sheets have enabled ordering.

## Changes

- Preserve existing development priority-group tags and insertion caches instead
  of destroying and replaying a whole group's rules on incremental insertion.
- Give layer mode separate priority tag pools, including named and unlayered
  rules. Keep stable priority ordering and existing tag chunk limits.
- Cache sort-group lookups and unique layer-order metadata. Generate ordering
  declarations when that metadata changes, rather than sorting all historical
  rules on each flush. Update each touched sourcemap once per flush.
- Export `CSSPropertiesRaw`, an alias for upstream
  `CSS.Properties<string | number>`, and use it for style and class-name
  transformer output. Numeric lengths remain supported; the existing
  `CSSProperties` type continues to apply Fluentic's value filtering.
- Change the direct `csstype` dependency from `3.2.3` to `^3.2.4`, allowing
  consumers to resolve newer 3.x definitions without another Fluentic release.

## Migration and limitations

No configuration migration is required. `flush()` remains synchronous. HMR rule
replacement and development mode changes can still rebuild affected sheets.

Existing consumer lockfiles retain their resolved `csstype` version until updated.
The range does not opt into future major versions. Fluentic's lockfile pins the
version used for its own validation.

A local Chromium benchmark inserting 800 unique rules one at a time after a
selector-sheet rule, with sourcemaps enabled, measured:

| Development mode | Before fix | After fix |
| ---------------- | ---------: | --------: |
| Sort             |   1,354 ms |    144 ms |
| Layer            |   3,880 ms |    218 ms |

The patched incremental insertion removed zero existing style tags. These are
synthetic browser measurements, not application latency guarantees. The consuming
financial-report application has not been retested with this package. Production
insertion performance was not benchmarked.

## Bundle measurements

Reports and documentation were regenerated from beta.19 with Vite 8.0.16 and
gzip level 9. Exact minified gzip sizes:

| Surface                             |  Bytes | Change from beta.18 |
| ----------------------------------- | -----: | ------------------: |
| Development runtime                 | 29,932 |                +315 |
| Extracted production runtime        |  5,097 |                   0 |
| Extracted JSX runtime               |  2,849 |                   0 |
| Extracted generated helpers         |    878 |                   0 |
| Optional named tokens               |  1,225 |                   0 |
| Full client production runtime      | 29,910 |                +320 |
| Server extracted production runtime |  5,163 |                   0 |

The full client runtime increase includes the shared ordering metadata cache.
Measurements are independent and must not be added together. See
`reports/bundle-size.json` for all surfaces and methodology.

## Validation

- Frozen-lockfile installation, versioned package build, generated declarations,
  and bundle report update passed with pnpm 10.17.1.
- `pnpm release:check` passed end to end, including bundle report freshness,
  workspace lint, formatting, documentation checks, and all workspace typechecks.
- All 472 library/compiler/runtime tests and three bundle-report tests passed.
  New regression cases cover late priorities, stable tag identity, chunking,
  sourcemap preservation, named layers, and global groups in both dev modes.
- All example and benchmark builds passed. Next.js production verification
  confirmed extracted CSS and rendered routes for `/`, `/ssg`, `/ssr`, `/rsc`,
  and `/client`.
- The packed beta.19 package passed strict TypeScript 5.9 and 7 consumers with
  Bundler, Node16, and NodeNext resolution. Tests verify the public
  `CSSPropertiesRaw` export, numeric transformer lengths, upstream values, and
  rejection of invalid property values. No implementation sources entered the
  consumer type programs.
- React, Preact, Solid, and Tailwind tarball consumer builds passed.
- During development, 48 Chromium cascade and layer-preamble cases passed across
  both priority modes, named/unlayered rules, global groups, important
  declarations, and enabled/disabled CSS layers.

## Release scope

Prepared for the beta channel with local annotated tag `v0.1.0-beta.19`.
npm publication, remote push, and GitHub Release creation have not been performed.
