# @fluentic/style v0.1.0-beta.5

## Highlights

This version expands Fluentic Style beyond regular element styles into attachable selector sheets, Preact css-prop support, and better interop tools for real third-party component styling.

### Selector Sheets

- Added `style.selector(...)` targets and `createSheet(...)` from `@fluentic/style/css`.
- Selector sheets attach through generated Fluentic classes instead of emitting global CSS.
- Added `&` and `&?` selector handling for attached-element and portal-friendly rules.
- Added selector sheet extraction, token overrides, debug class names, source tracing, and sourcemap support.

### Third-Party Styling

- Added `createStyleTarget(...)` for explicit DOM targets such as `document.body`.
- Added shared-target reference counting for overlapping portal users.
- Added a React Select selector-sheet example and refreshed the third-party styling guide.

### Composition

- `combineStyle(...)` can now compose sheets directly.
- Added `combineStyle.with(...)` and array-only `combineStyle.multi(...)` for cache-friendly composition.

### Framework Support

- Added Preact css-prop support through `CssPropPresets.Preact`.
- Added runtime adapters, JSX types, and a Vite Preact example.
- Kept plugin css-prop configuration focused on `CssPropPresets`.

### Priority And Interop

- Added `style.weight(...)` as the style-object counterpart to `className.weight(...)`.
- Added `style.important(...)` and `className.important(...)` for interop cases that need emitted `!important`, especially selector sheets wrapping third-party CSS.

### Size

The extracted production runtime remains under the 5 KB min+gzip budget:

- extracted production runtime: `4.92 KB` min+gzip
- extracted JSX runtime: `2.73 KB` min+gzip
- extracted generated helpers: `778 B` min+gzip

## Selector authoring and compatibility

Pass an array to target several selectors. Comma-separated selector strings are
rejected by the selector-sheet API. Sheets remain attached through Fluentic's
generated classes; creating a sheet does not by itself make its rules global.

`createStyleTarget` manages explicit DOM targets and reference-counts shared
users, which matters when several portal components attach styles to the same
node. `combineStyle.multi` accepts arrays; `combineStyle.with` provides a reusable
composition helper.

The bundle figures above are historical beta.5 measurements. Later releases
changed sheet layering defaults (beta.10), framework type opt-ins (beta.7), and
named layer support (beta.13); consult those notes when upgrading further.
