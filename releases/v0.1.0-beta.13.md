# @fluentic/style v0.1.0-beta.13

This beta adds named cascade layers for selector sheets and fixes compiler
extraction of inline curried selector calls. App-wide resets can stay scoped to
`body` or an app root, and valid curried syntax now extracts in production as
well as working at runtime.

## Changes

- Extract inline curried selector calls such as
  `style.selector('h1')({ fontSize: '1.5rem' })`, including selector arrays,
  reusable style fragments, and chained conditions. The direct second-argument
  form remains preferred; both forms are supported.
- Accept `boolean | string` in the individual `createSheet` `layer` option.
  `layer: 'reset'` uses `@layer reset`; `layer: '.reset'` uses
  `@layer <layerNamespace>.reset` (`css.reset` by default).
- Support named layers in compiler extraction, development and production runtime
  sheets, and server rendering and hydration payloads. Named layers work even
  when ordinary style layering is disabled. Boolean behavior is unchanged, and
  the global `css.layer.sheet` option remains boolean.
- Honor explicitly configured layer positions in `css.layers` without duplicating
  named layers at `$layer`. Keep rules and generated class identities distinct
  across different named layers.
- Document scoped resets and verify string layer options against packed generated
  declarations in the strict consumer matrix.
- Fix Node-only test/build URL imports so release checks do not confuse DOM and
  Node URL types with the installed Node declarations.

## Usage and upgrading

After publication:

```sh
pnpm add @fluentic/style@0.1.0-beta.13
```

Existing calls need no migration. For a scoped reset:

```tsx
import { style } from '@fluentic/style';
import { createSheet } from '@fluentic/style/css';

const reset = createSheet({ layer: 'reset' }, [
  style.selector(['&', '&::before', '&::after', '*', '*::before', '*::after'], {
    boxSizing: 'border-box',
  }),
  style.selector('&', { margin: 0 }),
]);

const app = <div css={reset}>{/* app content */}</div>;
```

Configure the plugin's CSS options to place the reset before Fluentic styles:

```ts
stylePlugin({
  css: {
    layers: ['reset', '$layer', 'overrides'],
  },
});
```

For a relative layer, list its resolved name in `css.layers`, such as `css.reset`.
Naming a layer does not remove class scoping: `&` targets the attached element;
plain selectors target descendants. Attach the sheet to `body` to reset `body`
itself. Normal unlayered declarations still outrank layered declarations, and
CSS reverses layer precedence for `!important` declarations.

### Curried selector extraction

The compiler now extracts this valid form, which previously remained runtime
code:

```ts
export const appDefaults = createSheet({ layer: true }, [
  style.selector('h1')({ fontSize: '1.5rem' }),
]);
```

For new inline declarations, prefer the direct second argument:

```ts
export const appDefaults = createSheet({ layer: true }, [
  style.selector('h1', { fontSize: '1.5rem' }),
]);
```

Both forms emit equivalent CSS and retain the sheet's scope and layer. Reusable
named targets such as `const h1 = style.selector('h1'); h1(styles)` continue to
work. Existing curried code does not need rewriting; rebuild it with beta 13 to
pick up the extraction fix.

## Validation

`pnpm install --frozen-lockfile` completed using the pinned pnpm 10.17.1.
`pnpm release:check` passed:

- Lint, formatting, LLM documentation checks, and all 25 workspace TypeScript
  projects. The previously observed Node/DOM URL type conflicts are fixed.
- All 374 library, compiler, runtime, sheet, and snapshot tests, including named
  layer resolution, class scoping, explicit ordering, server payloads, and
  curried/direct extraction equivalence across boolean and named layers.
- Package JavaScript/declarations and configured example and benchmark builds.
- Next.js production verification of extracted CSS and rendered routes `/`,
  `/ssg`, `/ssr`, `/rsc`, and `/client`.
- Isolated packed-package export and declaration checks under Bundler, Node16,
  and NodeNext ESM resolution, using `strict`, `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes`, and `skipLibCheck: false`. The consumer fixture
  accepts absolute and relative string sheet layers and curried selector calls,
  and rejects numeric layers.
- React, Preact, Solid, and Tailwind examples type-checked and built against the
  beta 13 tarball. Consumer programs did not load Fluentic implementation sources
  for types, and the Vite adapter imported without separately installing Babel.

As in beta 12, Next.js integration declarations are checked in Bundler mode;
Next.js's own declarations do not pass the Node16/NodeNext declaration matrix.
No other validation gates were waived.
