---
title: Styling Third-Party Components
description: Use selector sheets when a component library owns fixed internal class names.
---

Most Fluentic styles start from a simple assumption: your component owns the
markup. You put `css={styles.root}` on the root, `css={styles.label}` on the
label, and scopes or slots can follow the elements that you render.

A third-party component breaks that assumption. It may render the real input,
button, menu item, or dropdown for you. Sometimes it gives you a `className` for
the outer component, but the pieces you actually need to style live behind fixed
library class names such as `.react-select__control` or `.ant-select-selector`.
Sometimes the menu is rendered in a portal under `document.body`, outside the
wrapper where your component styles normally live.

Selector sheets are the escape hatch for that situation. They let you write
manual selectors for the third-party class names while keeping the rules inside
Fluentic's normal style world: generated class names, token overrides,
extraction, debug data, and sourcemaps still work. The result is not global CSS.
A sheet only applies when you attach the generated sheet class to an element or
target.

## A Wrapper That Owns The Boundary

Imagine a small wrapper around React Select. React Select owns the inner DOM, but
your wrapper owns the boundary where styles enter the component.

First define the tokens and the selector contract near the wrapper styles:

```ts
import { createTokens, style } from '@fluentic/style';
import { createSheet } from '@fluentic/style/css';

const selectTokens = createTokens({
  accent: '#2563eb',
  panel: '#eff6ff',
  text: '#1e3a8a',
});

const selectors = {
  control: style.selector('&?.react-select__control'),
  value: style.selector('&?.react-select__single-value'),
  menu: style.selector('&?.react-select__menu'),
  option: style.selector('&?.react-select__option'),
};
```

The selectors are manual because the third-party library owns those class names.
The selector targets are still Fluentic values. Calling one with a style object
creates a selector override, similar in spirit to calling a slot with a slot
override.

```ts
const selectSheet = createSheet([
  selectors.control({
    border: '1px solid',
    borderColor: selectTokens.accent,
    borderRadius: 10,
    backgroundColor: selectTokens.panel,
  }),
  selectors.value({
    color: selectTokens.text,
    fontWeight: 650,
  }),
]);

const compactSheet = createSheet([
  selectors.control({
    minHeight: 36,
    borderRadius: 6,
  }),
  selectors.value({
    fontSize: 13,
  }),
]);
```

Then attach the sheet to the wrapper and let React Select render inside it:

```tsx
import { combineStyle, type StyleTheme } from '@fluentic/style';

export function Select(props: {
  compact?: boolean;
  theme?: StyleTheme;
}) {
  const css = combineStyle(
    selectSheet,
    props.theme,
    props.compact && compactSheet,
  );

  return (
    <div css={css}>
      <ReactSelect classNamePrefix="react-select" unstyled />
    </div>
  );
}
```

The wrapper receives Fluentic's generated sheet class. The emitted CSS is scoped
under that class, so the third-party selectors do not start affecting the rest of
the page.

## Why `&?` Exists

A normal descendant selector such as `.react-select__control` works when the
sheet class is attached to a wrapper and the third-party element is inside it. A
leading `&` works when the generated sheet class is attached to the exact
third-party element you are selecting.

Portal and wrapper APIs often make you choose between those two shapes. `&?`
means "match either one":

```ts
const control = style.selector('&?.react-select__control');
```

That selector can match both of these cases:

```css
:where(.sheetClass).react-select__control { ... }
:where(.sheetClass) .react-select__control { ... }
```

This keeps a selector contract reusable when the same class may appear on the
attached element in one library mode and below the attached element in another.

There are still guardrails. A selector is one selector at a time; do not use a
comma-separated selector list. Use an array instead:

```ts
const field = style.selector([
  '.react-select__control',
  '.react-select__input-container',
]);
```

If you use `&`, keep it at the beginning and do not add whitespace after it.
That rule prevents selector sheets from reaching upward outside the element or
target where you chose to attach them.

## Local Themes Without App Themes

A third-party wrapper often wants local component themes: blue select, rose
select, compact select, warning select. You do not need an app-wide
`createTheme(...)` just to do that. A sheet can carry token overrides beside
selector styles.

```ts
const blueSheet = createSheet([
  selectTokens.accent('#2563eb'),
  selectTokens.panel('#eff6ff'),
  selectTokens.text('#1e3a8a'),
]);

const roseSheet = createSheet([
  selectTokens.accent('#c0265a'),
  selectTokens.panel('#fce7ef'),
  selectTokens.text('#8f1238'),
]);
```

Pass the chosen token sheet into `combineStyle(...)` with the component sheets:

```tsx
const css = combineStyle(
  selectSheet,
  props.theme,
  props.compact && compactSheet,
);
```

The selector rules read the same tokens as ordinary Fluentic styles. In dev they
resolve through runtime styles; in extracted builds they become atomic CSS with
the same token identity. That is the useful part of the escape hatch: the
selector is manual, but the values are still structured.

## Portal Menus

Dropdowns and popovers are the second common problem. Your wrapper may receive
the control, but the menu is mounted elsewhere:

```txt
<div class="your-wrapper sheetClass">
  <div class="react-select__control">...</div>
</div>

<body>
  <div class="react-select__menu">...</div>
</body>
```

The wrapper sheet cannot reach that menu unless you intentionally attach a sheet
to the portal target too.

```ts
const menuSheet = createSheet([
  selectors.menu({
    border: '1px solid',
    borderColor: selectTokens.accent,
    backgroundColor: '#fff',
  }),
  selectors.option({
    color: selectTokens.text,
    fontSize: 14,
  }),
]);
```

`createStyleTarget()` is the low-level helper for attaching a resolved style prop
to any element that is not rendered by your JSX tree.

```tsx
import { createStyleTarget } from '@fluentic/style/css';
import { useEffect, useRef, useState } from 'react';

function useStyleTarget() {
  const [target] = useState(() => createStyleTarget());
  const destroyTimer = useRef<number | null>(null);

  useEffect(() => {
    if (destroyTimer.current !== null) {
      window.clearTimeout(destroyTimer.current);
      destroyTimer.current = null;
    }

    return () => {
      destroyTimer.current = window.setTimeout(() => {
        target.destroy();
        destroyTimer.current = null;
      });
    };
  }, [target]);

  return target;
}
```

The cleanup is delayed so React Strict Mode does not remove the target class
between the intentional development remount.

In the component, resolve both the wrapper sheet and the menu sheet in one pass.
Attach the wrapper result to your wrapper and apply the menu result to the portal
target.

```tsx
import { combineStyle, type StyleTheme } from '@fluentic/style';

export function Select(props: {
  compact?: boolean;
  portalTarget: HTMLElement | null;
  theme?: StyleTheme;
}) {
  const target = useStyleTarget();
  const rootCss = combineStyle(
    [selectSheet, menuSheet],
    props.theme,
    props.compact && compactSheet,
    props.compact && compactMenuSheet,
  );
  const menuCss = combineStyle(
    menuSheet,
    props.theme,
    props.compact && compactMenuSheet,
  );

  target.apply(props.portalTarget, menuCss, {
    enabled: !!props.portalTarget,
  });

  return (
    <div css={rootCss}>
      <ReactSelect menuPortalTarget={props.portalTarget} unstyled />
    </div>
  );
}
```

Including `menuSheet` in `rootCss` keeps the non-portal case working, where the
menu is rendered below the wrapper. Applying `menuCss` to the portal target
covers the portal case. If different select instances need different menu
themes, give each instance its own portal target; attaching conflicting selector
sheets to `document.body` means both sheets can match the same third-party class
names.

## Debug Class Names

Selector sheets stay atomic. A sheet with two selector properties produces two
generated classes, and a later sheet that sets the same selector property
replaces the earlier class for that resolved style prop.

In debug mode, sheet selector classes use a shorter default format than ordinary
atomic classes:

```css
:where(.sheet-color-red--abc) .react-select__single-value { color: red }
```

The selector is intentionally omitted by default because third-party selectors
can be long. If you want it while debugging, configure `sheetClassNameFormat`:

```ts
configureStyleRuntime({
  css: {
    debugClassName: true,
    sheetClassNameFormat: 'sheet-[(selector)-](property)[-(value)]--$hash',
  },
});
```

## When This Is The Right Tool

Use selector sheets when the important styling hooks are fixed third-party class
names, class name prefixes, or portal nodes that sit outside your wrapper.

If the library lets you pass `className` or `style` directly to the exact element
you want to style, use the smaller bridge from
[Interop With Non-Fluentic APIs](./interop-with-non-fluentic-apis). Selector
sheets are for the moment when you need manual selectors, but you still want
Fluentic's tokens, extraction, debugging, and explicit attachment model.
